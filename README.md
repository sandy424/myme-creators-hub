# MYME Creators Hub

게임을 만드는 사람들이 모여 작품을 나누고, 동료와 협업하며 함께 성장하는 커뮤니티의 React 프론트엔드입니다.

기본적으로 백엔드 없이 실행되는 로컬 테스트 모드를 사용합니다. 별도의 서버나 데이터베이스는 포함되어 있지 않습니다.

최근 기능 반영: **2026-10-23**

## 실행 방법

Node.js **22.13 이상**이 필요합니다.

```sh
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. 개발 서버는 해당 주소와 포트를 사용하며, 5173 포트가 사용 중이면 실행되지 않습니다.

Windows PowerShell에서 실행 정책으로 `npm.ps1`이 차단되면 `npm.cmd install`, `npm.cmd run dev`처럼 실행하세요.

| 명령                   | 설명                                          |
| ---------------------- | --------------------------------------------- |
| `npm run dev`          | 개발 서버 실행                                |
| `npm run build`        | `dist/`에 배포용 파일 생성                    |
| `npm run preview`      | 빌드 결과 미리보기                            |
| `npm test`             | API·권한·데이터 처리·React 렌더링 자동 테스트 |
| `npm run format:check` | Prettier 형식 검사                            |
| `npm run format`       | Prettier 형식 적용                            |

## 기술 구성

- React 19, Vite 8, JavaScript / JSX
- Tailwind CSS v4와 `@tailwindcss/vite`
- shadcn/ui 방식의 Card·Carousel 구성, Embla Carousel 기반 슬라이드
- `clsx`, `tailwind-merge`를 사용하는 클래스 병합 함수
- 로컬 Pretendard Variable 글꼴, 보라색·검은색·회색 계열 테마
- 해시 기반 화면 이동과 공통 `HubContext`

스타일은 각 JSX의 `className`에서 수정합니다. 공통 색상은 `src/index.css`의 `@theme`에 정의된 `brand`, `ink`, `muted`, `line`, `canvas`를 사용합니다. 브라우저 기본 폼 스타일을 유지하기 위해 Tailwind Preflight 대신 공통 기본 스타일을 적용합니다.

`@/` 경로는 `src/`를 가리키며, `vite.config.js`와 `jsconfig.json`에 설정되어 있습니다.

## 주요 기능

### 메인·사이드 패널

- 최근 커뮤니티 글, 게시판 카테고리, 동료 찾기, 공식 행사·교육 진입점을 제공합니다.
- 왼쪽 행사 배너는 **높이 520px**을 유지하며 **5초마다 자동 전환**됩니다. 좌우 버튼, 드래그, 방향키 이동과 순환을 지원합니다.
- 마우스 호버·키보드 포커스 시 자동 전환을 멈추고, 일시정지·재생 버튼을 제공합니다. 다이얼로그가 열리거나 브라우저 탭이 숨겨진 동안에는 자동으로 넘기지 않습니다.
- 행사 배너를 클릭하면 현재 표시 중인 행사의 상세 내용이 바로 열립니다.
- 오른쪽에는 포인트 잔액과 동료가 공유한 게시글·프로젝트를 표시합니다. 동료 인원·프로필 목록은 활동 패널에 표시하지 않습니다.
- 사이드 패널은 스크롤을 따라오지 않습니다. 왼쪽 패널은 화면 너비 1200px 이상, 오른쪽 패널은 1000px 이상에서 표시합니다.
- 헤더·푸터는 전체 너비를 사용하고, 본문과 양측 패널 사이 간격은 화면 폭에 맞춰 조정합니다.

### 커뮤니티

- 카테고리별 목록, 글 작성·상세 보기, 댓글·대댓글, 좋아요, 링크 복사를 지원합니다.
- 카테고리에서 글 작성을 시작하면 해당 게시판이 미리 선택됩니다.
- 작성자에게만 **수정·삭제** 버튼을 표시합니다. 저장 처리에서도 작성자 권한을 검사합니다.
- 수정 시 기존 제목·본문·카테고리·관련 링크·첨부자료를 불러오며 댓글·좋아요는 유지합니다.
- 삭제 확인 후 게시글과 연결된 댓글·좋아요·첨부자료를 제거합니다.
- 관련 HTTPS 링크는 선택 사항입니다. 파일 선택·드래그 앤 드롭으로 첨부할 수 있으며, **최대 5개 / 전체 2MB**를 허용합니다.

### 동료·프로필·팀 협업

- 동료 찾기, 동료 요청·수락·취소, 내 프로필 수정과 공개 프로필 조회를 제공합니다.
- 프로필 사진 선택·삭제, 국가 검색, 소개·포트폴리오·공개 범위·메시지 수신 언어를 설정할 수 있습니다.
- **팀 협업에는 내가 만든 프로젝트와 팀원으로 참여 중인 프로젝트만 표시합니다.** 참여 여부는 회원 ID로 구분합니다.
- 다른 회원의 작성·참여 프로젝트는 **해당 회원의 공개 프로필**에서 확인하고 상세 화면으로 이동합니다.
- 프로젝트 상세에는 작성자와 참여 구분을 표시하며, 다른 사람의 프로젝트 배지는 `○○님의 프로젝트`로 표시합니다.
- 팀 구성은 동료 목록의 드롭다운에서 여러 명 선택할 수 있습니다. 선택한 팀원은 제거할 수 있고, 기존 직접 입력 정보는 유지 여부를 선택할 수 있습니다.
- 프로젝트 소개·진행 상태·팀 구성·외부 작업 공간 링크를 관리합니다. 수정 권한은 작성자에게만 있습니다.
- 커리어 경력은 등록 후 수정할 수 있습니다.

### 공식 행사·교육

- 포스터가 있는 일정 목록과 월별 달력을 제공합니다. 모바일에서는 달력이 위에 표시됩니다.
- `전체 / 행사 / 교육` 필터와 별도의 `모집 중` 조건을 함께 적용합니다.
- 모집 상태를 `모집 예정 / 모집 중 / 마감 임박 / 마감`으로 표시합니다.
- 날짜 선택, 월 전체 보기, 이전·다음 달, 이번 달 이동과 페이지당 4개 목록을 지원합니다.
- 여러 날 이어지는 일정은 기간에 포함된 모든 날짜에 표시합니다. 월과 하루라도 겹치는 일정은 해당 월 목록에 포함됩니다.
- 포스터는 전체가 보이도록 표시하며, 이미지가 없거나 로딩에 실패하면 대체 문구를 표시합니다.
- 상세 내용·신청 링크, 내부 스크롤, ESC·닫기 버튼·키보드 포커스 처리를 지원합니다.
- 현재 일정은 `src/schedules.js`의 **예시 데이터**입니다. 행사·신청 링크가 예시임을 화면에 표시합니다.

### 알림·채팅

- 댓글·답글·수신 메시지·동료 요청/수락 알림과 계정별 읽음 상태를 관리합니다.
- 알림 클릭 시 게시글 또는 대화로 이동하고, 확인 중인 게시글·대화의 알림은 읽음 처리합니다.
- 헤더에는 읽지 않은 알림 수를 0개일 때도 표시하며, 99개를 초과하면 `99+`로 표시합니다.
- 받은 메시지는 프로필의 **메시지 수신 언어**로 자동 번역합니다. 보낸 메시지는 원문을 유지합니다.
- 수신 언어를 지정하지 않은 기존 계정은 첫 번째 활동 언어를 사용하며, 인식되지 않으면 한국어를 사용합니다.
- 번역 중 표시, 원문 보기, 오류 시 원문 표시·재시도를 제공합니다.
- 번역 구현은 MyMemory API를 사용합니다. **수신 메시지 원문이 외부 번역 서비스로 전송**되며 인터넷 연결이 필요합니다. 긴 메시지 분할, 보이는 메시지만 번역, 계정·언어별 sessionStorage 캐시를 적용합니다.

### 포인트 지갑 초안

- 잔액과 전체·적립·사용 내역, 공식 기회로 이동하는 버튼을 제공합니다.
- 사이드 패널에서 지갑과 `상품 구매 / 현금 전환` 화면을 열 수 있습니다.
- 창작 리소스·교육 이용권·굿즈는 **예시 상품**입니다. 가격·필요 포인트는 확정되지 않았습니다.
- 현금 전환 비율·최소 포인트·신청 절차는 준비 중입니다. **실제 구매·포인트 차감·현금 전환은 수행하지 않습니다.**

## 로컬 데이터와 테스트

- 처음에는 회원·게시글·프로젝트·채팅·포인트 데이터가 비어 있습니다. 행사 예시 일정은 별도로 생성됩니다.
- 테스트 계정과 콘텐츠는 **현재 브라우저의 localStorage**에 저장합니다. 서버 DB나 다른 브라우저·기기와 공유되지 않습니다.
- 로그인은 **탭별 sessionStorage**에 보관하므로 같은 브라우저의 두 탭에서 서로 다른 계정으로 테스트할 수 있습니다.
- 게시글·댓글·채팅 등은 같은 브라우저의 탭 사이에서 공유합니다. 알림과 읽음 상태는 계정별로 관리합니다.
- 동료 찾기에 공개되려면 프로필 공개를 선택해야 합니다. 동료 요청·수락 후 프로젝트 팀원 선택과 동료 활동 표시를 확인할 수 있습니다.
- 예전 팀 구성 문자열은 자동으로 회원과 연결되지 않습니다. 참여 프로젝트로 분류하려면 드롭다운에서 해당 회원을 선택해 저장하세요.
- 로컬 인증은 UI 테스트용 시뮬레이션입니다. 실제 서비스 비밀번호 대신 테스트용 비밀번호를 사용하세요. 브라우저 저장소는 실제 인증·접근 제어를 대신하지 않습니다.
- 브라우저 사이트 데이터를 삭제하면 로컬 계정·콘텐츠가 사라집니다. 중요한 자료의 영구 저장 용도로 사용하지 마세요.

자동 테스트는 메모리 저장소와 렌더링 환경을 사용하며, 화면의 브라우저 데이터를 테스트 픽스처로 사용하지 않습니다.

## 실제 API 연결

기본 모드는 `mock`입니다. 실제 서버를 연결하려면 프로젝트 루트에 `.env`를 만들고 설정합니다.

```dotenv
VITE_API_MODE=server
VITE_API_PROXY_TARGET=http://localhost:3001
```

환경 변수 변경 후 개발 서버를 다시 실행하세요. 서버 주소는 예시이며 별도로 구현한 API 서버가 실행 중이어야 합니다.

`src/api.js`는 `/api/account/` 경로에 요청하고 `credentials: 'same-origin'`을 사용합니다. 실제 서버가 세션 쿠키·인증·권한 검사·검증·저장을 구현해야 합니다. `VITE_API_PROXY_TARGET`은 개발 서버 프록시 설정입니다. 배포 환경에서는 별도의 동일 출처 API 또는 리버스 프록시 설정이 필요합니다.

| 요청              | 메서드 | 주요 입력·출력                                                     |
| ----------------- | ------ | ------------------------------------------------------------------ |
| `me`              | GET    | 현재 계정·개인 상태                                                |
| `signup`, `login` | POST   | 가입·로그인 정보                                                   |
| `logout`          | POST   | 빈 객체                                                            |
| `state`           | POST   | `{ state: { user, career, ... } }`                                 |
| `community`       | GET    | 회원·게시글·프로젝트·대화·알림·`selfId`                            |
| `read-notices`    | POST   | `{ ids: [...] }`, 해당 계정의 알림 읽음 처리                       |
| `publish-post`    | POST   | title, body, category, relatedUrl, attachments                     |
| `update-post`     | POST   | id와 수정한 게시글 필드, 작성자 권한 필요                          |
| `delete-post`     | POST   | id, 작성자 권한 필요                                               |
| `comment`         | POST   | postId, text, parentId                                             |
| `like`            | POST   | postId, liked                                                      |
| `save-project`    | POST   | id(수정), title, summary, state, teamMembers, legacyMembers, links |
| `connection`      | POST   | peerId, operation(request/cancel/accept)                           |
| `send-message`    | POST   | peerId, text, lang                                                 |

프로젝트·프로필·동료 활동을 연결하려면 다음 관계를 유지해야 합니다.

- 프로젝트 `ownerId`와 회원 `accountId`는 계정 ID입니다.
- 프로젝트 `teamMembers`의 `{ id, name }`에서 `id`는 동료 목록의 회원 ID이며, `community.selfId`와 비교합니다.
- `canEdit`는 현재 계정의 작성자 여부입니다. 실제 서버에서도 수정·삭제 권한을 검사해야 합니다.
- 행사 일정은 계정 API와 별개로 `src/schedules.js`를 사용합니다. 실제 일정 연동 시 이 공급 부분과 `EventNews.jsx`의 `schedules` 입력을 연결하고 예시 표시·링크를 교체하세요.

## 아직 연결되지 않은 기능

- 실제 이메일 인증과 비밀번호 재설정 메일
- 서버 기반 포인트 지급, 상품 주문·포인트 차감, 현금 전환·정산
- 실제 공식 행사 신청·신청 내역 조회와 운영 일정 API
- QA·번역 품앗이 요청·정산

이 저장소에는 프론트엔드 소스, 정적 자산, 테스트용 API 어댑터와 자동 테스트가 포함됩니다. 백엔드 서버, 실제 데이터베이스, 운영 계정·세션·비밀번호는 포함하지 않습니다.
